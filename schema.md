## 1. Core — Users & Auth

### `users`

> Stores registered user accounts. `email` is the unique login identifier. Passwords are never stored in plain text — only the bcrypt hash is persisted.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated unique user identifier |
| `email` | `VARCHAR` | **NOT NULL**, **UNIQUE** | User's email address — used as the login identifier |
| `username` | `VARCHAR` | **NOT NULL** | Display name chosen at registration (min 2 chars enforced at API layer) |
| `password_hash` | `VARCHAR` | **NOT NULL** | bcrypt hash (cost 10) — plaintext password is never stored |
| `refresh_token` | `TEXT` | Nullable | Current valid refresh token; set to `NULL` after logout |
| `created_at` | `TIMESTAMP` | `DEFAULT now()` | Registration timestamp (without time zone) |

## 2. Market Data — Stocks & Prices

### `stocks`

> The master catalogue of all tracked securities. Acts as the parent table referenced by `stock_prices`, `technical_indicators`, `news`, and `user_watchlist` via foreign key on `ticker`.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `ticker` | `VARCHAR` | **Primary Key** | Normalised ticker symbol, e.g. `BBCA.JK`, `AAPL` |
| `company_name` | `VARCHAR` | **NOT NULL** | Full company name — used to build richer GNews search queries |
| `sector` | `VARCHAR` | Nullable | Industry sector classification |
| `last_updated` | `TIMESTAMP` | `DEFAULT now()` | Timestamp of the last metadata refresh (without time zone) |

---

### `stock_prices`

> Stores daily OHLCV (Open, High, Low, Close, Volume) price data fetched from Yahoo Finance. The composite unique constraint `UNIQUE (ticker, record_date)` ensures exactly one row per ticker per trading day, enabling safe `ON CONFLICT` upserts.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated row identifier |
| `ticker` | `VARCHAR` | **NOT NULL**, **FK → `stocks(ticker)`** | Stock symbol |
| `record_date` | `DATE` | **NOT NULL**, **UNIQUE with `ticker`** | Trading date; composite constraint: `UNIQUE (ticker, record_date)` |
| `open` | `NUMERIC` | Nullable | Opening price for the trading session |
| `high` | `NUMERIC` | Nullable | Daily high price |
| `low` | `NUMERIC` | Nullable | Daily low price |
| `close` | `NUMERIC` | Nullable | Closing / last traded price |
| `volume` | `BIGINT` | Nullable | Total shares traded during the session |
| `created_at` | `TIMESTAMP` | `DEFAULT now()` | DB insertion timestamp (without time zone) |

> **Unique Constraint Name:** `unique_ticker_date` on `(ticker, record_date)`

## 3. Market Data — Technical Indicators & News

### `technical_indicators`

> Stores computed RSI-14 values and trend signals for each ticker per day. Generated by the Python Data Science microservice during the EOD ingestion pipeline. The composite unique constraint `UNIQUE (ticker, record_date)` prevents duplicate entries for the same ticker on the same day.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated row identifier |
| `ticker` | `VARCHAR` | **NOT NULL**, **FK → `stocks(ticker)`** | Stock symbol |
| `record_date` | `DATE` | **NOT NULL**, **UNIQUE with `ticker`** | Calculation date; composite constraint: `UNIQUE (ticker, record_date)` |
| `rsi_14` | `NUMERIC` | Nullable | RSI value calculated over a 14-period window |
| `trend_status` | `VARCHAR` | Nullable | Signal string: `Overbought`, `Oversold`, or `Neutral` |
| `created_at` | `TIMESTAMP` | `DEFAULT now()` | DB insertion timestamp (without time zone) |

> **Unique Constraint Name:** `unique_ticker_date_indicator` on `(ticker, record_date)`
>
> **Retention Policy:** Rows older than 130 calendar days are automatically pruned by the daily EOD cron job.

---

### `news`

> Stores news articles fetched from GNews API, enriched with AI-generated sentiment scores. The `url` column is the natural deduplication key — insertions use `ON CONFLICT (url) DO NOTHING` to prevent duplicate articles.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated row identifier |
| `ticker` | `VARCHAR` | Nullable, **FK → `stocks(ticker)`** | Associated ticker symbol |
| `title` | `VARCHAR` | **NOT NULL** | Article headline |
| `description` | `TEXT` | Nullable | Article snippet or summary |
| `url` | `VARCHAR` | **NOT NULL**, **UNIQUE** | Canonical article URL — conflict resolution key |
| `source_name` | `VARCHAR` | Nullable | Publisher name, e.g. `CNBC Indonesia` |
| `published_at` | `TIMESTAMP` | **NOT NULL** | Publication datetime from GNews (without time zone) |
| `sentiment_score` | `NUMERIC` | Nullable | Confidence score `0.0–1.0` from the AI sentiment pipeline |
| `sentiment_label` | `VARCHAR` | Nullable | Sentiment result: `Positif`, `Negatif`, or `Netral` |
| `created_at` | `TIMESTAMP` | `DEFAULT now()` | DB insertion timestamp (without time zone) |

> **Fault Tolerance:** If the AI service is unavailable during ingestion, articles are still upserted with `sentiment_label = NULL` and `sentiment_score = NULL`. News data is **never lost** due to an AI outage.

## 4. User Features — Watchlist & Chat

### `user_watchlist`

> Tracks which stock tickers each user has added to their personal watchlist. The composite unique constraint `UNIQUE (user_id, ticker)` prevents a user from adding the same ticker twice.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated row identifier |
| `user_id` | `UUID` | **NOT NULL**, **FK → `users(id)`** | Owning user |
| `ticker` | `VARCHAR` | **NOT NULL**, **UNIQUE with `user_id`** | Normalised ticker symbol; composite constraint: `UNIQUE (user_id, ticker)` |
| `added_at` | `TIMESTAMP` | `DEFAULT now()` | Timestamp when the user added this ticker (without time zone) |

> **Unique Constraint Name:** `unique_user_ticker` on `(user_id, ticker)`

---

### `chat_history`

> Persists conversational turns between users and the RAG AI mentor. Each exchange is stored as **two sequential rows** — one with `sender_role = 'user'` and one with `sender_role = 'ai'` — allowing the AI microservice to reconstruct full conversational history in chronological order.

| Column | Data Type | Constraints / Default | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | **Primary Key**, `DEFAULT gen_random_uuid()` | Auto-generated row identifier |
| `user_id` | `UUID` | **NOT NULL**, **FK → `users(id)`** | Owning user |
| `message` | `TEXT` | **NOT NULL** | The message content (user query or AI reply) |
| `sender_role` | `VARCHAR` | **NOT NULL** | Identifies the turn author: `'user'` or `'ai'` |
| `created_at` | `TIMESTAMP` | `DEFAULT now()` | Message timestamp (without time zone) |

## 5. Relationship Diagram

```
users (id PK)
├── user_watchlist (user_id FK) ──► stocks (ticker PK)
│                                      ├── stock_prices (ticker FK)
│                                      │     └── UNIQUE (ticker, record_date)
│                                      ├── technical_indicators (ticker FK)
│                                      │     └── UNIQUE (ticker, record_date)
│                                      └── news (ticker FK)
│                                            └── UNIQUE (url)
└── chat_history (user_id FK)
      └── UNIQUE (user_id, ticker) [on user_watchlist]
```

| Relationship | Type | Constraint Name |
| :--- | :--- | :--- |
| `user_watchlist.user_id` → `users.id` | Many-to-One | `user_watchlist_user_id_fkey` |
| `user_watchlist` — unique per user+ticker | Composite Unique | `unique_user_ticker` |
| `chat_history.user_id` → `users.id` | Many-to-One | `chat_history_user_id_fkey` |
| `stock_prices.ticker` → `stocks.ticker` | Many-to-One | `stock_prices_ticker_fkey` |
| `stock_prices` — unique per ticker+date | Composite Unique | `unique_ticker_date` |
| `technical_indicators.ticker` → `stocks.ticker` | Many-to-One | `technical_indicators_ticker_fkey` |
| `technical_indicators` — unique per ticker+date | Composite Unique | `unique_ticker_date_indicator` |
| `news.ticker` → `stocks.ticker` | Many-to-One | `news_ticker_fkey` |
| `news` — unique per URL | Single Unique | `news_url_key` |
